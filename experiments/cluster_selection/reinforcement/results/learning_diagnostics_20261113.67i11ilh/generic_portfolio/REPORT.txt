Combining generic cluster constructors: same sixteen test puzzles

The round-robin portfolio does not beat its strongest individual member at the
same allowance in this experiment. Its expanded allowance solves 11/16 without
branching; the teacher alone solves 13/16. More allowance is useful here, but
mixing every source uniformly is not the best allocation we tested.

The expert is a domain-specific reference with 256-core/10M-work/1M-entry limits,
exact unary projections and no generic episode cap. Generic methods use 64 cores,
6 open variables, 1M work,100K intermediate entries, domain-compacted contractions
and no cumulative-work limit. Every full solve is valid; the root counts as one
DFS node. The same test set has been reused, so all additions are exploratory.

What is combined

The fixed source order is structural heuristic, supervised eight-anchor masks,
teacher-trained sequential constructor, original REINFORCE checkpoint, its
success-replay continuation, and selected Q-learning checkpoint. One- and
eight-anchor masks share weights, so only the eight-anchor variant is included.
Random initialization is a control, not a trained portfolio member. No weights
were retrained or selected using these outcomes.

Existing ConstructionEnsemble and ConstructionPolicy perform the interleaving.
The cursor advances after each proposal. A chosen cluster is contracted under
current domains, temporary-summary GAC retains pruning, and all proposal streams
restart after useful pruning. Duplicate clusters are removed; exhausted sources
yield to the remaining ones. The contraction allowance is shared by the whole
portfolio, not granted independently to every member.

The shared 32 arm gets 8,192 aggregate construction/search steps per refresh;
its six sources get about 1,365 steps each. The shared 192 arm gets 49,152 steps,
8,192 per source. Single-source 192 controls receive the same 49,152 aggregate steps.
This shares prescribed limits, not actual contractions, tensor work or CPU time.
The two refreshed-structural controls use the same regeneration schedule without
learned sources, distinguishing that change from portfolio complementarity.

Why there is a second192 portfolio

Source accounting found that the initial portfolios contracted no structural
proposals. Structural generation uses its requested list size to allocate search
across seeds; requesting 192 while granting that source 8,192 steps did not produce
an executable structural contribution. The separately frozen structural_cap32
diagnostic retains the original H32 list size, same six source order, same 192
total contractions and same 49,152 aggregate steps. It was declared after inspecting
the initial source counters and remains a post-hoc test-set diagnostic.

The diagnostic really uses every source. Its totals are:

Its result remains 26 nodes and 11 root solves. These are exactly the replay192
root solves, and a strict subset of the teacher192 root solves. Teacher192 also
solves positions 3 and 15 at the root. The source counters demonstrate useful
contributions in context, not that each source is necessary for a solved puzzle.
Q consumes 427 contractions without pruning here; equal source rotation therefore
spends capacity on currently unproductive proposals. This is evidence about
these selected weights and states, not a general claim against Q-learning.

The small shared 32 portfolio loses some root solves available to individual
policies. Splitting both contraction slots and decoding steps can sacrifice
individual strengths. The expanded portfolio recovers 11 root solves, but the
teacher alone improves from 28 to 20 nodes and from 10 to 13 root solves when given
the larger allowance. We therefore cannot credit the observed improvement over
the old32-allowance results to combining methods.

Verification and artifacts

There are 128 initial and 16 targeted new full solves, all valid and uncensored.
Independent audits checked all 419,904 original tensor-core supports plus givens,
frozen sources/data/checkpoints, training/test separation, per-episode caps and
source accounting. No portfolio root is novel relative to both standalone 192
teacher and replay arms; no extra cluster-proof replay was needed.

Production code, supervised training, ongoing GPU jobs, old checkpoints and old
results are unchanged. New adapters and results are confined to this directory.
protocol.json/summary.json/audit.json describe the initial comparison; the
structural_cap32 subdirectory contains its own frozen runner/protocol/results/
audit. comparison.json and nodes.csv join these with the earlier controls.
